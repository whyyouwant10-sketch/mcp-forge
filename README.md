# MCP Forge

> **Early development:** MCP Forge is an experimental generator. The CLI and
> generated-project contracts may change before a stable release.

MCP Forge turns a local OpenAPI 3.0/3.1 JSON or YAML document into a
 deterministic TypeScript MCP server skeleton. Generation is deterministic and
 offline: the generated server receives an injectable HTTP transport, while
 the fixture client tests request construction without making network calls.

## Quick start

```sh
npm ci
npm run build
node dist/cli.js validate --input test/fixtures/pets.yaml
node dist/cli.js generate --input test/fixtures/pets.yaml --output generated/pets
npm test
```

The sample commands produce output like this:

```text
valid OpenAPI 3.0.3 document
generated 2 tool(s) in 13 files: generated/pets
```

The generated directory contains a manifest, README, TypeScript project,
runtime transport, generated tool/type modules, and an in-memory fixture client:

```text
generated/pets/
├── .mcp-forge-manifest.json
├── README.md
├── package.json
├── tsconfig.json
├── src/
│   ├── generated-tools.ts
│   ├── generated-types.ts
│   ├── index.ts
│   ├── server.ts
│   ├── transport.ts
│   └── http/
└── test/
```

`generated/` is ignored because generated projects are build artifacts for
local use. The package's `dist/` directory is likewise generated by the build;
it is included in an npm package when a release is assembled, but is not source
controlled here.

## What is supported

The current implementation supports local `$ref` values; path, query, header,
and cookie parameters; JSON and `application/x-www-form-urlencoded` request
bodies; JSON and text responses; and API key, bearer, and basic security
schemes. Strict validation is enabled by default. The CLI provides `validate`
and `generate` commands plus `--help` and `--version`.

Generated servers expose `tools/list` and `tools/call` over newline-delimited
JSON-RPC stdio. Runtime HTTP access is behind `HttpTransport`; the default
transport uses `fetch` only in the generated server process.

## Limitations

Remote `$ref` URLs, OAuth and OpenID Connect flows, multipart and binary
payloads, WebSockets, callbacks, webhooks, and non-HTTP operations are not
supported in this early implementation. The generator does not infer behavior
from prose or examples, and it does not provide a general-purpose REST SDK.
Unsupported constructs fail in strict mode rather than being silently emitted.

See [`docs/SPEC.md`](docs/SPEC.md) for the detailed design contract and
[`docs/TEST_REPORT.md`](docs/TEST_REPORT.md) for the latest verification record.

## Credentials

Generated runtimes read credentials only from the documented environment
variables when the source specification requires them:

- `MCP_FORGE_API_KEY`
- `MCP_FORGE_BEARER_TOKEN`
- `MCP_FORGE_BASIC_USERNAME`
- `MCP_FORGE_BASIC_PASSWORD`

Credential values are not written to generated metadata, fixtures, manifests,
descriptions, or logs.
